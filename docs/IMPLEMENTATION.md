# Состояние прототипа

## Архитектура

- Autoloads: Constants → EventBus → GameManager. Локальная БД сохранений — `SaveDatabase` (RefCounted, экземпляр в GameManager). GameManager владеет данными; сцены только отображают их и вызывают проверяемые команды.
- WorldTile назван не TileData, чтобы не конфликтовать с встроенным Godot TileData; файл соответствует ТЗ `scripts/world/TileData.gd`.
- Фракции индексируются по id из JSON, очередь хранит индекс слота отдельно. Поэтому человек может выбрать любую фракцию.
- Юниты создаются фабрикой из сцен. При смене игрового экрана они отсоединяются от сцены; очистка партии удаляет их. Ожидающие ходы ИИ отменяются через session token.
- UI строится GDScript в текстовых сценах. `TileInfoPanel`, `UnitInfoPanel`, `TurnPanel`, `AIThinkingIndicator`, `Tile` и `Fog` — места расширения; их функциональность сейчас интегрирована в HUD / WorldMap, отдельные сцены являются каркасами.
- Игровые события emit только в EventBus; сцены слушают события и создают текстовые эффекты.

## Сохранения

Локальная БД — один JSON-файл `user://saves/hexempire_saves.json`: словарь `slots`, в каждом метаданные (label, время, раунд, размер карты) и полный `state`. Запись атомарная через tmp + bak. Чтение отбрасывает записи, не прошедшие `GameManager.valid_snapshot`, поэтому один битый слот не ломает остальные. Это файл на устройстве, а не СУБД: нет индексов, транзакций и многопользовательского доступа; для одиночной игры этого достаточно. Старый `autosave.json` импортируется при первом запуске. Экран слотов — `scripts/ui/SaveSlotsController.gd`.

## Правила

Манхэттенская метрика: движения и дальность без диагоналей. Не добавлялись LOS/блокировка снарядов, они не были определены в ТЗ. Горы проходимы после Альпинизма, корабли — только вода. У кораблей пока нет высадки/перевозки армии.

Кулдауны, invisibility, buffs, срок жизни зверя, revive считаются в собственных ходах владельца. Паладин начинает со щитом и обновляет его автоматически каждые 3 своих хода. Невидимость не позволяет атаковать ассасина, но он физически занимает клетку. Руины дают 3 звезды один раз за всю партию. Деревни дают 1 базовую звезду +1 после Земледелия. Лес после Охоты дает 1 звезду, только если клетка получила владельца посещением.

XP: убийство +2, захват +3; пороги — расходуемые 3/6/12/20. Превышение сохраняется. После каждого повышения требуется выбрать перк (у ИИ выбирается автоматически); следующий уровень не пропускает выбор. Перк способности единожды сокращает ее cooldown на 1 (в том числе сокращает цикл пассивного щита).

Hard minimax — ограниченный локальный поиск, не реализация полного обещанного «2 хода вперед». В симуляции учитываются HP, щит, защита местности, контратака, смерти и владение городом после движения. Ответ противника пока только удар с текущей позиции; нет симуляции найма, движения врага или способностей. Планируемый кандидат из 6 лучших по эвристике перепроверяется реальной моделью. Координация — последовательное движение с обновлением занятости, не полноценная система окружения. Экономика — приоритет технологий/резерв под таверну, не глобальная оптимизация.

## Проверки

`tests/SmokeTests.gd`: JSON catalogs, локальная БД (автосохранение, именованные слоты, удаление, отказ битых снимков), все размеры/количества игроков, движение, бой, найм, tech gates, экономика, таверна, пять героев, perks/revive, local/JSON roundtrip, malformed saves, три ИИ, победа/ничья.

`tests/supabase_rls.sql`: отдельный SQL тест политик для двух пользователей и anon. Требует реальной локальной БД Supabase, не работает как обычный GDScript тест.

Перед релизом нужны реальный Web-экспорт, UI-проверка на разных экранах, Android/iOS сборки, подключение настоящего Supabase, аудио, баланс и более полный планировщик ИИ.
