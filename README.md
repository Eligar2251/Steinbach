# HexEmpire — Godot 4.3+

Играбельный каркас пошаговой 4X на **квадратной сетке TileMapLayer**, вдохновленный Polytopia. В репозитории до этой реализации был только README. Точка входа: `scenes/Main.tscn`.

## Быстрый запуск на ПК

1. Установите **Godot 4.3 или новее**, обычную редакцию (не требуется .NET).
2. В менеджере проектов нажмите **Import**, выберите `project.godot` в корне репозитория.
3. Дождитесь импорта SVG и нажмите **F5** (запуск всего проекта).
4. «Новая игра» → размер, 2–4 игрока, отдельная сложность каждого ИИ, уникальные / случайные фракции → «Начать».

Командная строка, если Godot доступен как `godot`:

```sh
godot --editor --path .
# Запуск без редактора:
godot --path .
# Проверки (сначала импорт):
godot --headless --editor --path . --import
godot --headless --path . tests/SmokeTests.tscn
godot --headless --path . tests/SceneTests.tscn
```

**Ни интернет, ни Supabase для игры не нужны.** Сохранения пишутся во встроенную локальную БД игры — один JSON-файл на устройстве:

```
user://saves/hexempire_saves.json
```

Это не облако и не сервер: файл лежит в папке данных приложения Godot, рядом создается резервная копия `hexempire_saves.json.bak`. Старт — 5 звезд плюс доход первого хода. После хода ИИ выполняется автосохранение (слот `autosave`), есть ручная запись в выбранный слот.

Где эта папка на диске:

| Система | Путь |
|---|---|
| Windows | `%APPDATA%\Godot\app_userdata\HexEmpire\saves` |
| Linux | `~/.local/share/godot/app_userdata/HexEmpire/saves` |
| macOS | `~/Library/Application Support/Godot/app_userdata/HexEmpire/saves` |
| Браузер | IndexedDB браузера, обычной папки нет |

Папку можно открыть прямо из игры: «Продолжить • локальная БД» → «Открыть папку сохранений»; либо в редакторе Godot: Project → Open User Data Folder.

### Управление

- Выберите своего юнита, затем отмеченную клетку — движение; видимого врага в пределах дальности — атака.
- После атаки движение заканчивается. После движения можно атаковать. Найм начинает действовать со следующего собственного хода.
- Перетаскивание мышью / пальцем — камера; колесо / жест масштабирования — zoom.
- Для найма освободите клетку своего города. Корабль нанимается на соседнюю свободную воду.
- Посещайте клетки в радиусе 2 от своих городов для населения. Улучшение требует населения и звезд; уровни 3/4 требуют технологий.
- Архитектура + город уровня 3 + 8 звезд → таверна → герой. Перки выбираются в панели героя; портрет кликабелен.

## Сохранения: встроенная локальная БД

В игре есть своя БД сохранений без сервера и без Supabase:

- **8 слотов** + отдельный слот `autosave`.
- В каждом слоте: карта, раунд, число игроков, метка времени и полный снимок партии.
- Запись атомарная: `tmp` → резервная копия → переименование. Поврежденный слот не затирает остальные.
- Загрузка проверяет снимок (`GameManager.valid_snapshot`) **до** создания объектов; битый слот просто не открывается.
- Старый `user://saves/autosave.json` из прошлых версий при первом запуске переносится в слот `autosave`.
- Слоты удаляются из того же экрана. Облако Supabase опционально и теперь не основной путь.

Как сохраниться и загрузиться:

- В партии: **Сохранить (автослот)** или **Сохранить в слот…** в верхней панели / меню.
- В главном меню: **Продолжить • локальная БД** → выбрать слот → «Загрузить».

Сохранения привязаны к устройству и профилю ОС: копирование `hexempire_saves.json` на другой компьютер переносит партии.

## Можно ли через браузер?

**Да, через Web-экспорт Godot**, а не через открытие `.tscn` или `project.godot` в браузере.

1. Editor → **Manage Export Templates** → установить шаблоны той же версии, что редактор.
2. Project → Export → готовый профиль **Web**. Здесь Compatibility / WebGL 2 и **отключены потоки** (Godot 4.3+).
3. Экспортировать в `export/web/index.html` (папка не попадает в Git).
4. Отдать **все** файлы экспорта HTTP-сервером:

```sh
mkdir -p export/web
godot --headless --path . --export-release Web export/web/index.html
python3 -m http.server 8000 --bind 0.0.0.0 --directory export/web
# На своем ПК открыть http://localhost:8000
```

Для публикации подойдет HTTPS static hosting с поддержкой `.wasm` (`application/wasm`). Через `file://` работать не будет. Для текущего однопоточного экспорта COOP/COEP и SharedArrayBuffer не требуются; при включении потоков они понадобятся. JSON-справочники явно включены в экспорт через `include_filter`.

В браузере `user://` хранится в IndexedDB, а не в обычной папке; очистка данных сайта удалит сохранения. Приватный режим может не сохранять данные. Для облака нужны интернет и настроенный Supabase; реальный браузерный экспорт и mobile-производительность требуют отдельной проверки на устройствах. На мобильных браузерах доступны клавиатура и эмуляция мыши от touch, но жесты и UI пока прототипные.

## Supabase

Подробная инструкция: [docs/SUPABASE.md](docs/SUPABASE.md).

- Миграция: `supabase/migrations/202610070001_initial_schema.sql`.
- Таблицы: `profiles`, `game_saves` с приватными слотами пользователя.
- Auth: регистрация / email + пароль / refresh session.
- RLS: каждый authenticated пользователь читает и изменяет **только свои** записи; anon не получает доступ.
- Godot-клиент: `scripts/services/SupabaseClient.gd` (`HTTPRequest`, REST).
- URL + **публичный** anon/publishable key задаются в «Настройки / облако»; сессия, пароль и refresh token не записываются на диск.
- В меню партии → «Облако Supabase» → вход → сохранение / загрузка одного слота `autosave`.

Это **опциональное** облачное хранение одиночных партий, не multiplayer и не серверная проверка ходов. Клиентское состояние нельзя использовать как доверенный лидерборд. Создание удаленного Supabase-проекта и применение миграций выполняются отдельно владельцем проекта.

## Что реализовано

- Все три размера карты, seed-генерация, четыре фракции, стартовые биомы, сухопутные пути между столицами.
- TileMapLayer + раздельный туман исследования / текущей видимости, радиус 2 по Манхэттену.
- Все семь боевых юнитов из JSON; зверь призыва тоже в JSON. Движение с бюджетом, препятствиями, технологиями и фракционными бонусами.
- Бой с округлением формулы до целого HP, min 1, защита местности, контратака только с дистанции 1, смерть и автоматический захват.
- Пять героев, активные способности / пассивный щит, XP, два случайных перка, уровни 1–5, кулдауны и повторный найм после пяти своих ходов.
- Звезды, города 1–4, население посещениями, таверны, исследования и найм.
- Меню / лобби / HUD / дерево технологий / портрет с лором / результаты, анимированный фон и текстовые эффекты.
- Три политики ИИ, сохраненная память наблюдений (Medium 3 своих хода, Hard не забывает до опровержения), задержки и последовательная очередь.
- JSON-сохранения с версией, валидацией до загрузки и заменой через временный файл.

## Осознанные допущения и границы

Полный список: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md). Важное:

- **Hard — ограниченный minimax на 2 полухода, beam width 6**, не полный поиск двух ходов всех армий. Сейчас планируется перемещение и ответный удар видимого врага; атаки, технологии и экономика используют эвристики.
- ТЗ говорит «12 технологий», но перечисляет 9. Добавлены явно помеченные `extension`: Альпинизм, Торговля, Медицина. Для Великанов выбрана предпосылка Архитектура.
- Сохранения по умолчанию пишутся во встроенную локальную БД; Supabase — опция, не требуется для игры.
- Все изображения — **текстовые SVG-заглушки**, включая портреты; ни PNG, ни музыка, ни SFX, ни внешние шрифты не требуются. Пути картинок заданы в JSON. Пять способностей доступны с найма; перк способности улучшает кулдаун, а не разблокирует ее.
- Улучшение города пока ручное, стоит `уровень × 3` и требует `уровень × 2` населения. Трава вокруг стартового города исследуется в начале, население дают именно посещения.
- Лес / снег / пустыня стоят 2 движения. Юнит MOV 1 может войти в дорогую соседнюю клетку, израсходовав полный ход; иначе обычная пехота не могла бы вообще исследовать такие биомы.
- Потеря всех городов **или** всех юнитов означает выбывание; наблюдатель может продолжить оставшиеся ходы ИИ. При равных итоговых очках — ничья.
- Изученные, но не видимые клетки сохраняют текущие данные местности / города, скрывая юнитов (не отдельный last-seen снимок инфраструктуры).
- Нет сетевого мультиплеера, реальных аудио/арт-ассетов, релизных Android/iOS-пакетов, полного QA всех платформ.

## Как запустить игру без веба (самый короткий путь)

1. Скачайте **Godot 4.3+** (обычная версия, без .NET) с godotengine.org/download.
2. Распакуйте и запустите `Godot_v4.3-stable_win64.exe` (или версию для вашей системы). Ничего устанавливать не нужно.
3. В менеджере проектов нажмите **Import** и выберите файл `project.godot` в папке репозитория.
4. Нажмите **Import & Edit**, дождитесь импорта (несколько секунд).
5. Нажмите **F5** — откроется главное меню игры.
6. **Новая игра** → размер карты → соперники-ИИ → **Начать →**.

Без редактора, если `godot` доступен в PATH:

```sh
godot --path /путь/к/Steinbach
```

Дальше: локальные сохранения доступны в меню «Продолжить • локальная БД». Интернет, аккаунт и Supabase для этого не нужны.

`scenes/` — экраны и объекты; `scripts/` — GDScript; `data/` — справочники; `assets/` — заменяемые заглушки; `supabase/` — миграции; `tests/` — headless проверки и RLS SQL.

Перед изменением файла прочитайте его полностью. Боевые характеристики не хардкодить: источники — `data/units.json` и `data/heroes.json`. Общие игровые параметры — `scripts/core/Constants.gd`. Не добавлять `@tool` без необходимости, секреты, `.godot/`, экспортированные бинарники и большие артефакты.
